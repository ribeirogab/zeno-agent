## Approach

## File Structure

Files **modified**:

- `infra/Dockerfile` — add a `RUN` line installing `uv` at a pinned version (0.11.7). Stage placement: in the **`base`** stage. `runtime` extends from `base` (`FROM base AS runtime`), so the binary in `/usr/local/bin` is inherited by `runtime`. `base` runs as root throughout (the only stage where a system-wide `curl … | sh` install is safe); `runtime` switches to `USER node` before `CMD`. See Phase 1 below for the exact insertion point.

## Phase ordering

### Phase 0 — Spec finalization (3-review)

### Phase 1 — Prereq gate + Dockerfile change

**Pre-step (gate)**: verify `apps/worker/scripts/regenerate-catalog-tool-snapshots.mjs` has spec 0039's patch (`grep "skip.*: missing env var" apps/worker/scripts/regenerate-catalog-tool-snapshots.mjs` should match a `console.warn(...)` line). If not, merge 0039 first — Phase 3 of this spec will abort otherwise.

- Add to the **`base`** stage (NOT `runtime`). The `base` stage runs as `root` throughout, and `runtime` extends from `base` (`FROM base AS runtime`), so any binary installed in `/usr/local/bin` in `base` is automatically present in `runtime`. Putting it in `runtime` is fragile because `runtime` switches to `USER node` before `CMD` (line 74 of the current Dockerfile), and a `RUN curl … | sh` that writes to `/usr/local/bin` requires root.
- Insert the `uv` install line in the `base` stage, after the AWS CLI install block and before the `corepack enable` line (around current line 22):
  ```dockerfile
  # Spec 0040: install `uv` for Python-based MCP servers (Klaviyo, Swarmia).
  RUN curl -LsSf https://astral.sh/uv/0.11.7/install.sh | UV_INSTALL_DIR=/usr/local/bin sh
  ```
  - Version `0.11.7` is current as of 2026-04-27 (verified against Astral's GitHub releases). The URL pattern `https://astral.sh/uv/<version>/install.sh` 301-redirects to the versioned `uv-installer.sh` artifact. Bumping the version is a separate one-line PR.
  - Inlining `UV_INSTALL_DIR=/usr/local/bin` into the same `RUN` ensures the env var is scoped to the install step only — it doesn't pollute `runtime`'s environment.
- Verify: `pnpm run docker:build` succeeds; `docker run --rm zeno-agent:dev uvx --version` prints a 0.11.x version. Run a second check as the `node` user (matches the runtime user): `docker run --rm --user node zeno-agent:dev uvx --version` should also work because the binary is in `/usr/local/bin` which is on root and node's `PATH`.

### Phase 3 — Tool list regeneration

- **Execution context**: runs on the host, not inside the container (catalog file is bind-mounted read-only; apps/ not mounted). Host needs `uv` installed (one-time): `curl -LsSf https://astral.sh/uv/0.11.7/install.sh | sh`.
- `PRIVATE_API_KEY=pk_… node apps/worker/scripts/regenerate-catalog-tool-snapshots.mjs --fetch-from-mcp`
- Confirms 60+ tools.
- **Note**: regen does NOT call `authCheckTool` (only `tools/list`). Real auth validation happens via the API smoke (`POST /catalog/klaviyo/test` — Phase 6) which DOES pass `authCheckTool`. A bad-but-syntactically-valid key may pass regen with empty tools — recover by running the API smoke separately, then re-running regen with a known-good key.
