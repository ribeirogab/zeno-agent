# Knowledge folder

This folder is the **shared brain** between you (the operator) and the Zeno agent. Drop one Markdown file per topic in here — products you build, processes you run, the glossary of your industry, your team, your habits, the projects in flight. The agent sees a compact table of contents in its system prompt every turn and reads individual files on demand when the conversation touches them.

> Docs: <https://docs.zeno-agent.dev/docs/knowledge>

## Layout

```
~/.zeno/profiles/<name>/knowledge/
├── _index.md       # auto-generated table of contents (do not edit)
├── _template.md    # blank note with the frontmatter shape
├── _README.md      # this file
└── your-notes.md   # everything else is yours
```

Files prefixed with `_` are meta — hidden by default in the dashboard tree and excluded from the agent's index. Use them for templates, scratch space, or readmes like this one.

Subfolders are fine. Group however helps you (`processes/`, `playbooks/`, `people/`, `architecture/` — your call). The agent doesn't care about hierarchy; the index flattens everything.

## How the agent uses it

1. **Boot.** The worker bind-mounts `knowledge/` read-only at `/app/knowledge` inside the container.
2. **Index.** `_index.md` (auto-generated by `zeno knowledge index <profile>` or refreshed on every file change) is injected as a `# Knowledge available` block in the cached system prompt. The block is capped at 8 KB — over that, it is truncated with a pointer telling the agent to use the Read tool.
3. **On demand.** When a turn's content matches an entry in the index, the agent calls Read on `/app/knowledge/<path>` to pull the full file body.

The agent never writes to this folder. All edits are yours.

## Frontmatter

YAML frontmatter at the top of each file customizes how the agent and dashboard surface it. All fields are optional. See `_template.md` for a fully-commented example.

| Key | Type | Default | What it does |
|---|---|---|---|
| `title` | string | first `# Heading`, then filename | Display name in the index, dashboard, and graph. |
| `description` | string | first paragraph of body (truncated to 120 chars) | One-line summary shown next to the file path in `_index.md` and in the system prompt. |
| `tags` | string[] | `[]` | Flat list for cross-cutting grouping. Surfaces as gold pill chips in the dashboard viewer and as peach nodes in the graph view. |
| `related` | string[] | `[]` | Wikilink-style slugs to other notes. Resolved by basename (`stack` → `stack.md`); use a path prefix to disambiguate (`engineering/stack`). |

You may add arbitrary additional keys — the dashboard's Properties block renders every key/value pair, so anything you add will show up.

## Wikilinks in the body

Reference another note with `[[slug]]`. Resolution rules:

- **Bare slug** (`[[stack]]`) matches any `.md` with that basename anywhere under `knowledge/`. Ambiguous matches resolve to `null`.
- **Path-prefix** (`[[engineering/stack]]`) requires the file to live under that subtree.
- **Unresolved** wikilinks render as a dimmed red span with a tooltip; in the graph they become ghost nodes (gray outline).

The dashboard's `/knowledge` page renders wikilinks as clickable links that swap the viewer without reloading.

## Useful CLI commands

```bash
zeno knowledge list <profile>      # print every file with title, tags, size
zeno knowledge index <profile>     # regenerate _index.md
zeno knowledge open <profile>      # open this folder in your OS file browser
zeno open <profile>                # open the dashboard at the /knowledge page
```

## Dashboard view

`http://localhost:<port>/knowledge` gives you two modes:

- **Graph** — Obsidian-style force-directed graph. Files are gray dots sized by degree, tags are peach dots, unresolved wikilinks are gray outlines. Hover highlights neighbors; click a file node to jump to its rendered content.
- **Files** — folder-tree sidebar + rendered markdown of the selected note, with the frontmatter shown as a Properties block above the body.

## Privacy

Nothing in this folder is committed to the Zeno repository — it lives entirely on your machine under `~/.zeno/profiles/<name>/`. Treat it as your private notebook. If you commit notes to your own repo for backup, audit them for secrets like you would any other source file.
